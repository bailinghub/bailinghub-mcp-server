# Agent Client SDK v0.6.0：把附件、任务和原调用接进客户端

发布版本：0.6.0。配套：Core 0.8.0 / Agent Client SDK 0.6.0 / DSH 0.6.0。相对上一公开版本的变化如下。

例如，客户端里的助手需要上传活动图片，再修改商城商品；用户关闭窗口后，还要能区分“等待审批”“已经执行”和“结果未确认”。本轮 SDK 为宿主提供这些步骤所需的接口、类型和可处理状态。SDK 不生成图片、不负责界面，也不替业务系统决定权限。

## 新增与改进

- **附件交付。** `uploadArtifact` / `getArtifact` 将获准图片绑定到明确的原目标，保存后取得 URL。确认丢失时核对原上传 ID，成功地址直接复用。图片文件来自宿主受控目录，不能把模型提供的任意路径交给 SDK 读取。
- **只读原调用回执。** `inspectInvocation` 与可能真正执行的 `resume` 分开。商品已批准不等于已上架，宿主可以只查询原结果，不把刷新面板变成业务派发。
- **任务协商与状态。** `getTaskControlCapabilities`、`getTask` 及可信宿主注入的 `taskBinding` 连接 Core 的固定成员和累计预算。SDK 不提供模型可用的创建任务、增额或换任务入口；多成员宿主必须核验整组。
- **能力数量与失败分类。** 保留搜索候选、加载状态、未知总数、原限流窗口与等待提示。临时传输故障、原授权变化、不支持、原记录不存在和结果未知保持不同处理方式。
- **刷新身份保护。** 刷新或状态查询发现原 Session / Client / 绑定发生变化时，拒绝替代身份并返回结构化原因；暂时网络失败仍允许原身份重试。取消和异步改绑不会被晚到回应覆盖。

## 宿主怎么升级

成套更新实际安装与 lock，确认每个消费者解析到同一个 SDK。保留原连接标识、Agent Session、固定范围、事件和各类持久记录；不要为升级重建授权。

读取任务或原回执需要原 `connectionKey` 和完整 `expectedBinding`。任务快照不是执行许可，最终权限、预算和派发由 Core 判断。先协商新接口；旧 Core 明确不支持时显示 unsupported，不把查询降级为 resume。

可复用的协议支持证明不包含业务权限、任务状态、预算或执行结果；不会免除逐次校验。SDK 不自动重放写操作。已发出但未知的结果使用原调用核对，不能改参数或换授权再试。

完整角色分工、060–062 迁移和启用顺序见[升级指南](UPGRADE_v0.6.0.md)。普通业务后端不用为这些宿主接口修改已有声明或审批；私有宿主负责自己的持久存储和界面。

## 与 MCP 使用方式的区别

本包同时提供独立 MCP 服务和宿主 SDK。这里的附件来源、会话面板、任务关联和跨轮工具复用需要宿主接入，不会因为 MCP Registry 更新就自动出现在所有 MCP 客户端。原固定路由的 Client Token job 流程保留；任务管理员凭据不进入模型工具。

已完成 SDK 回归及配套合成验证；升级时核对正式包版本与来源。历史调用若没有可信持久记录或原参数，不能从聊天文本补造恢复依据。
